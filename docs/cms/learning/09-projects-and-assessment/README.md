## Objectives

Demonstrate that you can build, operate, analyze, and design CMS systems rather than only describe their concepts.

## Project 1 — Mini CMS

Build a small CMS from application fundamentals.

### Required Scope

- authentication;
- administrator and editor roles;
- content types or articles;
- categories and relationships;
- drafts and publishing;
- revisions;
- permission checks;
- media upload;
- frontend rendering;
- audit fields;
- database migrations;
- basic automated tests.

### Evidence

Provide source code, database design, request-flow diagram, permission matrix, test instructions, and a short architecture decision record.

## Project 2 — CMS Extension Suite

Use an established CMS and create:

- one custom theme or template;
- one reusable module, block, or widget;
- one event-driven plugin;
- one substantial custom component or feature;
- one secured REST API or external integration.

Document installation, migration, permissions, compatibility, testing, update, and uninstall behavior.

## Project 3 — Headless CMS

Build a separated CMS backend and frontend.

### Required Scope

- content API;
- frontend website;
- draft preview;
- authentication for editorial actions;
- pagination and filtering;
- media delivery;
- webhook processing;
- cache invalidation;
- deployment instructions;
- failure and retry handling.

Explain why the project benefits from headless architecture and which new complexities it introduces.

## Project 4 — Enterprise CMS Design

Design and prototype selected critical flows for a platform with assumptions such as:

- 10 million content entries;
- 50 websites;
- 10 languages;
- 2,000 editors;
- approval workflows;
- permission-aware search;
- CDN and object storage;
- queue-based background processing;
- audit requirements;
- high availability and disaster recovery.

### Required Deliverables

- requirements and capacity estimates;
- content and permission models;
- architecture diagram;
- publishing sequence;
- media-processing flow;
- search-indexing flow;
- cache and invalidation strategy;
- consistency guarantees;
- failure scenarios;
- observability plan;
- deployment and migration strategy;
- trade-offs and alternatives.

## Professional Levels

### Beginner

- installs and operates a CMS;
- manages content, users, media, menus, and configuration;
- understands basic themes and plugins.

### Intermediate CMS Developer

- builds extensions and APIs;
- traces requests and database behavior;
- debugs routing, permissions, templates, and cache;
- deploys a reproducible CMS environment.

### Senior CMS Developer

- designs substantial extensions;
- reviews code and architecture;
- handles security, performance, migration, and integration concerns;
- mentors other developers.

### CMS Technical Lead

- defines module boundaries and engineering standards;
- coordinates delivery, testing, upgrades, and operations;
- reviews technical proposals and manages architectural risk.

### CMS Solution Architect

- selects platforms and solution patterns;
- designs traditional, headless, multi-site, and multilingual solutions;
- balances cost, delivery speed, maintainability, security, and scale;
- produces migration and operating models.

### CMS System Architect

- designs the CMS platform, infrastructure, extension ecosystem, data flows, reliability model, and operational boundaries;
- solves consistency, scaling, search, caching, media, and failure-recovery problems across the complete system.

## Final Assessment

You are ready to claim professional capability only when you can provide evidence for the following:

- [ ] I built and explained a mini CMS.
- [ ] I delivered custom extensions for an established CMS.
- [ ] I deployed and operated a CMS environment.
- [ ] I implemented a headless or decoupled solution.
- [ ] I investigated a real performance problem using measurements.
- [ ] I completed a security review and fixed verified risks.
- [ ] I designed cache invalidation, retries, and failure recovery.
- [ ] I produced a complete enterprise CMS system design.
- [ ] I can explain rejected alternatives and architectural trade-offs.
- [ ] I have handled real defects, upgrades, or incidents in a production-like environment.

The target after completing the roadmap and projects is **Senior CMS Developer with a path toward CMS Solution Architect**. The title **CMS Solution Architect** or **CMS System Architect** should be supported by repeated real-world design and operational experience, not only by completing study material.
