# jQuery 1.11.3 → 3.5.1 Direct Upgrade Gap Analysis

> **Purpose:** Provide a complete, reviewable compatibility-gap analysis for replacing jQuery `1.11.3` directly with jQuery `3.5.1`.
>
> **Upgrade mode:** **Direct upgrade** — the application does **not** deploy `1.12.x`, `2.x`, `3.0`, `3.1`, `3.2`, `3.3`, `3.4`, or `3.5.0` as production migration steps. Those releases are analyzed only because their changes are included in the final `3.5.1` behavior.
>
> **Primary rule:** The source version is already `1.11.3`, therefore it is newer than jQuery `1.9`. The official jQuery upgrade guidance allows moving directly to jQuery 3.x with **jQuery Migrate 3.x**. However, a direct replacement still crosses all breaking changes introduced by jQuery 3.0 and the security-driven HTML parsing change introduced by jQuery 3.5.0.

# 1. Executive Summary

## Direct upgrade

```text
jQuery 1.11.3
      │
      │  Direct dependency replacement
      │
      ▼
jQuery 3.5.1
```

This direct replacement skips the deployment of intermediate releases, but it does **not** skip their behavioral changes:

```text
1.11.3
   │
   ├── changes introduced in 1.12.x
   ├── major breaking changes introduced in 3.0
   ├── ready/error behavior changes from 3.1
   ├── dimensions/event/deprecations from 3.2
   ├── additional deprecations from 3.3
   ├── event/security behavior from 3.4
   ├── security-driven htmlPrefilter change from 3.5.0
   └── 3.5.0 regression fix from 3.5.1
   │
   ▼
3.5.1
```

## Overall assessment

| Area | Risk | Why |
|---|---|---|
| Core jQuery replacement | 🟠 High | Crosses the jQuery 3.0 major boundary |
| Old plugins/widgets | 🟠 High | May depend on removed/deprecated APIs or jQuery internals |
| Ajax | 🟠 High | jqXHR aliases removed; cross-domain script behavior changed |
| Deferred / Promise | 🟠 High | jQuery 3 adopts Promises/A+ behavior for `.then()` |
| Events | 🟠 High | Event aliases and `ready` event behavior changed |
| Selectors | 🟡 Medium | `:visible`, `:hidden`, invalid selectors and selector internals changed |
| Dimensions/layout | 🟡 Medium | Width/height can return fractional values and calculations changed |
| Data API | 🟡 Medium | Dashed data keys become camelCase in internal data object |
| HTML manipulation | 🟠 High | jQuery 3.5 changes `htmlPrefilter` behavior for security |
| Security | 🟢 Improvement | 3.5.1 contains security fixes missing from 1.11.3 |

### Main conclusion

> **A direct `1.11.3 → 3.5.1` upgrade is technically supported, but it must be treated as a high-risk compatibility change for a legacy application.**
>
> Do not evaluate risk by the number of version hops. Evaluate it by which APIs and behaviors the application actually uses.

# 2. Upgrade Shape

## Recommended implementation shape

```text
Step 0 — Inventory current jQuery usage
      ↓
Step 1 — Freeze baseline tests
      ↓
Step 2 — Replace 1.11.3 with 3.5.1 in DEV/STAGING
      ↓
Step 3 — Add jQuery Migrate 3.x development build
      ↓
Step 4 — Run static legacy API scan
      ↓
Step 5 — Run runtime flows + capture JQMIGRATE warnings
      ↓
Step 6 — Fix compatibility problems
      ↓
Step 7 — Remove jQuery Migrate
      ↓
Step 8 — Re-run full regression suite
      ↓
Step 9 — Security scan / duplicate-jQuery verification
      ↓
GO / NO-GO
```

## What this document does **not** require

The following versions are **not required as production deployment steps**:

```text
1.12.4
2.2.4
3.0.0
3.1.1
3.2.1
3.3.1
3.4.1
3.5.0
```

They are compatibility landmarks only.

Official jQuery guidance:

- <https://jquery.com/upgrade-guide/>
- <https://jquery.com/upgrade-guide/3.0/>

The jQuery upgrade guide states that applications already using jQuery `1.9` or later can move directly to a current jQuery release using jQuery Migrate 3.x as an upgrade aid.

| Level | Meaning |
|---|---|
| 🟢 Low | Patch/fix behavior; normal regression testing is usually enough |
| 🟡 Medium | Specific APIs or edge cases can change; targeted scan/test required |
| 🟠 High | Known breaking boundary; code review + Migrate + full regression required |
| 🔴 Blocker | Confirmed code/plugin cannot work on 3.5.1 without remediation |

# 5. Gap A — jQuery 1.11.3 → 1.12.x Behavior Included in the Target

## Risk

**🟡 Medium**, primarily because bug fixes can expose application assumptions.

jQuery `1.11.3` itself was a small hotfix release. jQuery `1.12.x` continued the 1.x compatibility line and did not intentionally create a new major compatibility boundary.

Official sources:

- `1.11.3`: <https://blog.jquery.com/2015/04/28/jquery-1-11-3-and-2-1-4-released-ios-fail-safe-edition/>
- `1.12.0`: <https://blog.jquery.com/2016/01/08/jquery-2-2-and-1-12-released/>
- `1.12.1`: <https://blog.jquery.com/2016/02/22/jquery-1-12-1-and-2-2-1-released/>
- `1.12.2`: <https://blog.jquery.com/2016/03/17/jquery-1-12-2-and-2-2-2-released/>
- `1.12.3`: <https://blog.jquery.com/2016/04/05/jquery-1-12-3-and-2-2-3-released/>
- `1.12.4`: <https://blog.jquery.com/2016/05/20/jquery-1-12-4-and-2-2-4-released/>

## Areas worth testing

- `.position()` behavior, especially old jQuery UI tooltip/layout integrations.
- `.prop("selected")` and option selection behavior.
- `:visible` selector behavior.
- `.load()` behavior.
- `$.get()` / `$.post()` option-object usage.
- Ajax requests using unusual ports or cross-domain detection.

## Direct-upgrade implication

You are not required to fix code specifically for 1.12 first. Instead, these behaviors should be included in the final 3.5.1 regression suite.

# 6. Gap B — The Major Boundary: jQuery 1.x → 3.0

## Risk

**🟠 High — this is the largest compatibility gap in the entire direct upgrade.**

Primary official documentation:

> <https://jquery.com/upgrade-guide/3.0/>

The sections below map directly to the categories in the official jQuery 3.0 Upgrade Guide.

---

## 6.1 Ajax

Official doc:

- <https://jquery.com/upgrade-guide/3.0/> — search `Ajax`

### GAP-3.0-AJAX-01 — jqXHR `.success()`, `.error()`, `.complete()` removed

Old:

```javascript
$.ajax(url)
  .success(onSuccess)
  .error(onError)
  .complete(onComplete);
```

Target:

```javascript
$.ajax(url)
  .done(onSuccess)
  .fail(onError)
  .always(onComplete);
```

> Important: `success`, `error`, and `complete` options inside the `$.ajax({ ... })` configuration object are different and remain valid in jQuery 3.0.

### GAP-3.0-AJAX-02 — Cross-domain script requests must be explicit

If remote content is intended to execute as JavaScript, specify:

```javascript
dataType: "script"
```

Do not rely on jQuery implicitly treating cross-domain responses as script.

### GAP-3.0-AJAX-03 — URL hash behavior changed

`$.ajax()` no longer strips a hash fragment before passing the URL to the transport.

### GAP-3.0-AJAX-04 — `$.get()` / `$.post()` gained settings-object signature

Usually non-breaking, but wrappers that inspect function signatures or arguments should be tested.

---

## 6.2 Attributes and Forms

Official doc:

- <https://jquery.com/upgrade-guide/3.0/> — search `Attributes`

### GAP-3.0-ATTR-01 — `.removeAttr()` no longer forces boolean property to `false`

Risk patterns:

```javascript
$checkbox.removeAttr("checked");
$option.removeAttr("selected");
$input.removeAttr("readonly");
```

Preferred dynamic-state API:

```javascript
$checkbox.prop("checked", false);
```

### GAP-3.0-ATTR-02 — Empty multi-select `.val()` result changed

Before:

```javascript
null
```

jQuery 3:

```javascript
[]
```

Audit code like:

```javascript
if ($select.val() === null) {
    // legacy assumption
}
```

### GAP-3.0-ATTR-03 — `.toggleClass()` signatures deprecated

Audit no-argument or boolean-only calls.

---

## 6.3 Core APIs

Official doc:

- <https://jquery.com/upgrade-guide/3.0/> — search `Core`

### GAP-3.0-CORE-01 — jQuery 3 core runs in strict mode

Most application code is unaffected, but integrations depending on deprecated caller/callee behavior or old runtime assumptions can break.

### GAP-3.0-CORE-02 — document-ready handlers become asynchronous

Do not depend on ready handlers executing synchronously because the document is already ready.

Risk:

```javascript
var initialized = false;

$(function () {
    initialized = true;
});

// Do not assume this is true immediately.
console.log(initialized);
```

### GAP-3.0-CORE-03 — `.context` and `.selector` removed

Audit plugins that access internal collection metadata:

```javascript
$obj.context
$obj.selector
```

### GAP-3.0-CORE-04 — `.size()` removed

Old:

```javascript
$(".item").size()
```

Target:

```javascript
$(".item").length
```

### GAP-3.0-CORE-05 — undocumented internals removed

High-risk for old plugins:

```text
jQuery.swap
jQuery.buildFragment
jQuery.domManip
```

Any third-party plugin using private/internal jQuery APIs must be reviewed or upgraded.

### GAP-3.0-CORE-06 — return values on empty sets standardized to `undefined`

Review logic that expects legacy values from getters on empty jQuery collections.

### GAP-3.0-CORE-07 — `jQuery.unique()` deprecated

Prefer:

```javascript
jQuery.uniqueSort()
```

### GAP-3.0-CORE-08 — `jQuery.parseJSON()` deprecated

Prefer:

```javascript
JSON.parse()
```

### GAP-3.0-CORE-09 — non-standard ready signatures deprecated

Preferred:

```javascript
$(function () {
    // init
});
```

## 6.4 Data API

Official doc:

- <https://jquery.com/upgrade-guide/3.0/> — search `Data`

### GAP-3.0-DATA-01 — dashed keys are camelCased in the returned data object

Example:

```javascript
$el.data("click-count", 3);
var data = $el.data();
```

Target object key:

```javascript
data.clickCount
```

Do not rely on:

```javascript
data["click-count"]
```

when reading the full internal data object.

---

## 6.5 Deferred / Promise

Official doc:

- <https://jquery.com/upgrade-guide/3.0/> — search `Deferred`

### GAP-3.0-DEFERRED-01 — `.then()` becomes Promises/A+ compatible

This is a major semantic change.

Key effects:

- `.then()` callbacks run asynchronously.
- exceptions thrown inside `.then()` become rejection values.
- returned thenables/promises are assimilated.
- rejection-handler return values can turn into fulfillment values.

Audit:

```text
.then(
.catch(
$.Deferred(
$.when(
.resolve(
.reject(
.notify(
```

### GAP-3.0-DEFERRED-02 — callback context changes

`.resolve()`, `.reject()`, and `.notify()` use `undefined` context rather than the associated promise object.

If code depends on `this` inside a Deferred callback, inspect it carefully.

### GAP-3.0-DEFERRED-03 — `$.when()` semantics changed

`then`-bearing objects are treated as thenables. Single/no-argument behavior is more Promise-like.

### GAP-3.0-DEFERRED-04 — `$.when()` progress forwarding removed

Do not rely on progress notifications being propagated by `$.when()`.

## 6.6 Dimensions

Official doc:

- <https://jquery.com/upgrade-guide/3.0/> — search `Dimensions`

### GAP-3.0-DIM-01 — `.width()` / `.height()` can return fractional numbers

Old code may assume integers:

```javascript
var width = $(el).width();
```

Do not rely on:

```javascript
Number.isInteger(width) === true
```

Review sliders, responsive menus, carousels, modal positioning, image sizing and custom layout calculations.

### GAP-3.0-DIM-02 — window `.outerWidth()` / `.outerHeight()` includes scrollbar dimensions

Review breakpoint code comparing jQuery dimensions with CSS media queries.

---

## 6.7 Effects

Official doc:

- <https://jquery.com/upgrade-guide/3.0/> — search `Effects`

### GAP-3.0-EFFECT-01 — `.show()`, `.hide()`, `.toggle()` respect stylesheets differently

Review widgets relying on jQuery restoring computed display values.

### GAP-3.0-EFFECT-02 — animations use `requestAnimationFrame`

Usually an improvement, but timing-sensitive tests/plugins should be validated.

### GAP-3.0-EFFECT-03 — `jQuery.fx.interval` deprecated

Audit code that adjusts animation timing globally.

---

## 6.8 Events

Official doc:

- <https://jquery.com/upgrade-guide/3.0/> — search `Event`

### GAP-3.0-EVENT-01 — `.load()`, `.unload()`, `.error()` event aliases removed

Legacy event form:

```javascript
$(window).load(fn);
$(window).unload(fn);
$(img).error(fn);
```

Target:

```javascript
$(window).on("load", fn);
$(window).on("unload", fn);
$(img).on("error", fn);
```

> Do not confuse event shorthand `.load(fn)` with Ajax `.load(url)`.

### GAP-3.0-EVENT-02 — `$(document).on("ready", fn)` removed

Use:

```javascript
$(fn);
```

### GAP-3.0-EVENT-03 — `jQuery.event.props` / `jQuery.event.fixHooks` removed

Old plugins extending jQuery's event normalization internals may fail.

### GAP-3.0-EVENT-04 — invalid delegated selectors throw immediately

Bad selectors may now fail at event registration rather than only when the event fires.

### GAP-3.0-EVENT-05 — `.bind()` / `.delegate()` deprecated

Prefer:

```javascript
.on()
.off()
```

### GAP-3.0-MANIP-01 — `.wrapAll(function)` callback invocation changed

The function is called once for the entire collection instead of behaving like `.wrap()`.

## 6.10 Offset

Official doc:

- <https://jquery.com/upgrade-guide/3.0/> — search `Offset`

## 6.11 Selectors

Official doc:

- <https://jquery.com/upgrade-guide/3.0/> — search `Selector`

### GAP-3.0-SELECTOR-01 — `:hidden` / `:visible` definition changed

Zero-width/zero-height elements can be treated differently if they still produce layout boxes.

High-risk UI areas:

- dropdown visibility checks;
- tabs;
- modal logic;
- hidden field logic;
- validation plugins;
- lazy loading;
- sliders/carousels.

### GAP-3.0-SELECTOR-02 — `$("#")` becomes invalid selector syntax

Dynamic selectors must never produce a bare `#`.

### GAP-3.0-SELECTOR-03 — custom-selector aliases deprecated

Audit:

```javascript
jQuery.expr[":"]
jQuery.expr.filters
```

Prefer supported selector-extension APIs.

### GAP-3.0-SELECTOR-04 — `$.escapeSelector()` added

Use it when IDs/classes contain selector-special characters.

`$.param()` no longer converts `%20` to `+`; the form-url-encoded conversion is handled in the Ajax path.

Review code that directly compares or signs serialized strings.

# 7. Gap C — jQuery 3.0 → 3.1.1

## Risk

**🟢/🟡 Low–Medium** once the application is already compatible with jQuery 3.0.

Official sources:

- <https://blog.jquery.com/2016/07/07/jquery-3-1-0-released-no-more-silent-errors/>
- <https://blog.jquery.com/2016/09/22/jquery-3-1-1-released/>

## Main observable gap — ready-handler exceptions

jQuery 3.0's Promise-based ready implementation could make errors in ready handlers difficult to see. jQuery 3.1 introduced `jQuery.readyException` and causes ready-handler exceptions to surface asynchronously.

Direct-upgrade effect:

> An error that existed in old code may suddenly become visible in the console after the upgrade. That is not necessarily a new bug introduced by jQuery; it may be an old application bug that was previously hidden.

### Test

- all `$(function () { ... })` initializers;
- `$(document).ready(...)` handlers;
- plugins initialized on ready;
- page-specific initialization scripts.

# 8. Gap D — jQuery 3.1.1 → 3.2.1

## Risk

**🟡 Medium** for layout/event-heavy legacy applications.

Official sources:

- <https://blog.jquery.com/2017/03/16/jquery-3-2-0-is-out/>
- <https://blog.jquery.com/2017/03/20/jquery-3-2-1-now-available/>

## Changes to include in direct-upgrade testing

### GAP-3.2-01 — dimensions behavior fixes

Width/height calculations were changed around CSS transforms and inline elements. `3.2.1` fixed regressions from `3.2.0`.

Test:

- sliders;
- carousels;
- sticky headers;
- responsive menus;
- modal centering;
- dynamic image sizing;
- tooltip positioning.

### GAP-3.2-02 — checkbox/radio click behavior

Event behavior for checkbox/radio controls changed and was partially reverted/fixed in `3.2.1`.

Test:

- custom checkbox/radio widgets;
- delegated click handlers;
- code reading `.prop("checked")` inside handlers.

### GAP-3.2-03 — new deprecations

Audit:

```text
jQuery.holdReady
jQuery.nodeName
jQuery.isArray
```

Official reference:

- <https://blog.jquery.com/2017/03/16/jquery-3-2-0-is-out/>

# 9. Gap E — jQuery 3.2.1 → 3.3.1

## Risk

**🟢/🟡 Low–Medium** for runtime behavior; **Medium** as a legacy-code cleanup signal.

Official sources:

- <https://blog.jquery.com/2018/01/19/jquery-3-3-0-a-fragrant-bouquet-of-deprecations-and-is-that-a-new-feature/>
- <https://blog.jquery.com/2018/01/20/jquery-3-3-1-fixed-dependencies-in-release-tag/>

## Main gap — deprecation wave

The following APIs were deprecated in the 3.3 line:

```text
jQuery.now
jQuery.isWindow
jQuery.camelCase
jQuery.proxy
jQuery.type
jQuery.isNumeric
jQuery.isFunction
event shorthand aliases
```

These APIs still exist in 3.5.1, but their presence in source code is technical debt and can produce Migrate warnings depending on the Migrate version.

### Direct-upgrade action

Do not block the `3.5.1` upgrade only because an API is deprecated and still works, unless:

- the API is already removed in the target;
- Migrate indicates a compatibility problem;
- a plugin depends on undocumented internals;
- the code is security-sensitive or clearly unsafe.

# 10. Gap F — jQuery 3.3.1 → 3.4.1

## Risk

**🟡 Medium**.

Official sources:

- <https://blog.jquery.com/2019/04/10/jquery-3-4-0-released/>
- <https://blog.jquery.com/2019/05/01/jquery-3-4-1-triggering-focus-events-in-ie-and-finding-root-elements-in-ios-10/>

## GAP-3.4-SEC-01 — Prototype pollution behavior fixed

jQuery 3.4 prevents deep `$.extend()` from writing an enumerable `__proto__` source property into `Object.prototype`.

Audit:

```javascript
$.extend(true, target, source)
```

Prioritize cases where `source` originates from:

- JSON responses;
- user-controlled data;
- URL/query parameters;
- local/session storage;
- third-party APIs;
- plugin configuration loaded dynamically.

### Security reference

- <https://blog.jquery.com/2019/04/10/jquery-3-4-0-released/>
- Search section: `Minor vulnerability fix: Object.prototype pollution`

## GAP-3.4-EVENT-01 — radio checked state during events

jQuery 3.4 fixed the checked state visible inside radio event handlers.

Audit code that reads radio state inside click/change handlers.

## GAP-3.4-EVENT-02 — native focus/blur triggering changes

jQuery 3.4.0 changed native focus/blur event handling and 3.4.1 fixed regressions, especially in older IE.

Test old form/UI plugins that programmatically call:

```javascript
.trigger("focus")
.trigger("blur")
.focus()
.blur()
```

## GAP-3.4-CSP-01 — script nonce / nomodule preservation

3.4 improves preservation of `nonce` and `nomodule` during DOM script manipulation. This is primarily an improvement but matters in CSP-heavy applications.

# 11. Gap G — jQuery 3.4.1 → 3.5.0

## Risk

**🟠 High — second most important direct-upgrade compatibility gate.**

Primary official documentation:

- <https://jquery.com/upgrade-guide/3.5/>
- <https://blog.jquery.com/2020/04/10/jquery-3-5-0-released/>

## GAP-3.5-HTML-01 — `jQuery.htmlPrefilter` behavior changed

Before 3.5.0, jQuery transformed some XHTML-style self-closing HTML strings into explicit open/close tag pairs.

Example legacy input:

```javascript
$("<div class='box' />")
```

The old regex-based normalization had security-sensitive edge cases. jQuery 3.5.0 changed `htmlPrefilter` so the HTML string is passed through rather than automatically rewritten by the legacy regex.

### Why this can break legacy code

Search for dynamically generated self-closing **non-void HTML elements**, for example:

```text
<div />
<span />
<p />
<section />
<a />
```

HTML void elements such as `br`, `img`, `input`, `hr`, `meta`, and `link` are a different case.

### Audit patterns

```text
.html(
.append(
.prepend(
.before(
.after(
.replaceWith(
$('<...')
$("<...")
$.parseHTML(
```

### Important security rule

Do **not** restore the old HTML-prefilter behavior as a permanent fix merely to make tests pass. The upstream documentation warns that restoring legacy behavior also restores the security-sensitive behavior that 3.5 was designed to remove.

If a temporary compatibility patch is used during investigation, it must be removed before the migration is considered complete.

Official reference:

- <https://jquery.com/upgrade-guide/3.5/>
- Search section: `jQuery.htmlPrefilter changes`

## GAP-3.5-DEPRECATION-01 — `jQuery.trim` deprecated

Prefer native string trimming where appropriate:

```javascript
value.trim()
```

## GAP-3.5-DEPRECATION-02 — Ajax event aliases deprecated

Prefer `.on(...)` based event registration.

# 12. Gap H — jQuery 3.5.0 → 3.5.1

## Risk

**🟢 Low**.

Official source:

- <https://blog.jquery.com/2020/05/04/jquery-3-5-1-released-fixing-a-regression/>

jQuery 3.5.0 changed an internal jQuery data object to use `Object.create(null)`. Some plugins expected normal objects and called `.hasOwnProperty()` directly, causing regressions. jQuery 3.5.1 reverted that specific change.

### Direct-upgrade implication

Because the final target is `3.5.1`, you receive the 3.5 security fixes **without** retaining that 3.5.0 data-object regression.

This is one reason `3.5.1` is a better target than exactly `3.5.0` for this migration.
