## Overview

### Target workflow

```text
jQuery 1.12.4
    ↓
jQuery 2.2.4
    ↓
jQuery 3.0.0
    ↓
jQuery 3.1.1
    ↓
jQuery 3.2.1
    ↓
jQuery 3.3.1
    ↓
jQuery 3.4.1
    ↓
jQuery 3.5.0
    ↓
jQuery 3.5.1
```

### Important migration principle

The jQuery project does **not** require an application already on jQuery `1.9+` to deploy every intermediate minor release. jQuery Migrate 3.x can be used when moving from jQuery `1.9+` to jQuery 3.x.

This workflow intentionally keeps intermediate checkpoints because legacy CMS applications may contain old templates, modules, plugins, widgets, and custom JavaScript. The checkpoints make regressions easier to isolate.

### Verified upstream facts vs project assessment

Every section distinguishes between:

- **Verified upstream facts** — documented behavior from the official jQuery upgrade guides or release notes.
- **Project risk assessment** — the estimated migration risk for a legacy application. This must be confirmed by code inspection and runtime testing.

---

## Risk Classification

| Risk | Meaning |
|---|---|
| 🟢 Low | Patch-level or highly backward-compatible change; normal regression testing is normally sufficient. |
| 🟡 Medium | Behavior can change in specific APIs, browsers, plugins, or edge cases. Targeted code inspection is required. |
| 🟠 High | Known breaking API/behavior boundary. Static scan + jQuery Migrate + full regression testing are required. |
| 🔴 Blocker | A confirmed dependency cannot operate on the target version and must be fixed/replaced before continuing. |

### Upgrade risk overview

| Step | Upgrade | Main gap | Project risk |
|---:|---|---|---|
| 1 | `1.12.4 → 2.2.4` | Old IE support removed from 2.x | 🟡 Medium |
| 2 | `2.2.4 → 3.0.0` | Removed APIs + Deferred/Ajax/event/ready behavior changes | 🟠 **High** |
| 3 | `3.0.0 → 3.1.1` | Ready-handler exceptions become visible; patch fixes | 🟢/🟡 Low–Medium |
| 4 | `3.1.1 → 3.2.1` | Dimensions, radio events, new deprecations | 🟡 Medium |
| 5 | `3.2.1 → 3.3.1` | Broad deprecation wave; plugin compatibility | 🟢/🟡 Low–Medium |
| 6 | `3.3.1 → 3.4.1` | Prototype-pollution fix + event/selector changes | 🟡 Medium |
| 7 | `3.4.1 → 3.5.0` | `htmlPrefilter` security-driven behavior change | 🟠 **High** |
| 8 | `3.5.0 → 3.5.1` | Regression fix for jQuery data objects | 🟢 Low |

> The two most important compatibility gates are **2.2.4 → 3.0.0** and **3.4.1 → 3.5.0**.

# Step 1 — 1.12.4 → 2.2.4

## Gap Summary

```text
1.12.4
   ↓
2.2.4

Primary gap:
Browser compatibility, not a large public API rewrite.
```

### Verified upstream facts

jQuery `1.12.4` and `2.2.4` were released together. Their APIs were intentionally closely aligned, but the 1.x branch retained compatibility code for Internet Explorer 6/7/8 while the 2.x branch did not.

The jQuery project stated that `1.12.4` and `2.2.4` themselves were small bug-fix releases and were not expected to introduce breaking changes compared with their preceding releases.

### Project risk assessment

**Risk: 🟡 Medium** for an old enterprise/CMS application.

The main risk is not normal jQuery API usage. The risk is code that depends on:

- IE 6/7/8;
- old DOM/event workarounds;
- browser sniffing;
- conditional IE logic;
- plugins that officially support only jQuery 1.x;
- duplicated jQuery copies loaded by legacy extensions.

## Code to inspect

Search browser-specific logic:

```bash
rg -n "MSIE|Trident|document\.documentMode|attachEvent|detachEvent|ActiveXObject" . \
  --glob '!node_modules/**' \
  --glob '!.git/**'
```

Search explicit jQuery version restrictions:

```bash
rg -n "jquery[-_. ]?1|1\.12\.4|jQuery\.fn\.jquery|jquery version" . \
  --glob '!node_modules/**' \
  --glob '!.git/**'
```

## Compatibility checklist

- [ ] Confirm IE 6/7/8 are not required by the supported-browser contract.
- [ ] Identify plugins that document jQuery 1.x-only support.
- [ ] Test selectors and traversal.
- [ ] Test form submit/change/click events.
- [ ] Test Ajax requests.
- [ ] Test animations and sliders.
- [ ] Test modals/dropdowns/navigation.
- [ ] Check for duplicated jQuery libraries.
- [ ] Confirm no new console exceptions.

## Exit Gate

```text
Supported browsers:          PASS
Critical pages:              PASS
Critical interactions:       PASS
Unexplained console errors:  0
Blocking 1.x-only plugins:   0
```

## Reference

- https://blog.jquery.com/2016/05/20/jquery-1-12-4-and-2-2-4-released/

# Step 2 — 2.2.4 → 3.0.0

## Gap Summary

```text
2.2.4
   ↓
3.0.0

Primary gap:
MAJOR compatibility boundary.
```

### Verified upstream facts

jQuery 3.0 intentionally removed deprecated public APIs, removed or hid undocumented internals, and changed several documented behaviors. The official jQuery 3.0 Upgrade Guide explicitly identifies multiple breaking changes.

jQuery officially recommends using **jQuery Migrate 3.x** when moving to jQuery 3.x.

### Project risk assessment

**Risk: 🟠 High**.

This is the checkpoint most likely to expose legacy application problems.

## High-priority breaking gaps

### 1. Removed `.size()`

```javascript
// Old
$(".item").size();

// Replacement
$(".item").length;
```

Search:

```bash
rg -n "\.size\s*\(" . --glob '*.{js,html,php}'
```

---

### 2. Removed `.andSelf()`

```javascript
// Old
$(".child").andSelf();

// Replacement
$(".child").addBack();
```

Search:

```bash
rg -n "\.andSelf\s*\(" . --glob '*.{js,html,php}'
```

---

### 3. Removed event shortcut methods `.load()`, `.unload()`, `.error()`

Old event usage:

```javascript
$(window).load(fn);
$(window).unload(fn);
$("img").error(fn);
```

Replacement:

```javascript
$(window).on("load", fn);
$(window).on("unload", fn);
$("img").on("error", fn);
```

> Do not confuse the removed event shortcut `.load(fn)` with jQuery's Ajax `.load(url)` method.

Search:

```bash
rg -n "\.(load|unload|error)\s*\(" . --glob '*.{js,html,php}'
```

---

### 4. Removed jqXHR `.success()`, `.error()`, `.complete()`

```javascript
// Old
$.ajax(url)
  .success(onSuccess)
  .error(onError)
  .complete(onComplete);

// Replacement
$.ajax(url)
  .done(onSuccess)
  .fail(onError)
  .always(onComplete);
```

Search:

```bash
rg -n "\.(success|error|complete)\s*\(" . --glob '*.{js,html,php}'
```

Review matches manually because the names may belong to unrelated APIs.

---

### 5. Document-ready handlers are asynchronous

jQuery 3.0 changed document-ready execution so ready handlers are asynchronous.

Potential risky pattern:

```javascript
var initialized = false;

$(function () {
  initialized = true;
});

// Legacy code may incorrectly expect this to already be true.
useValue(initialized);
```

Audit code that relies on execution order around:

```javascript
$(function () { ... });
$(document).ready(function () { ... });
```

---

### 6. Deferred/Promise behavior changed

jQuery Deferred became Promises/A+ compatible in jQuery 3.0.

High-risk areas:

- `.then()` chains;
- exception propagation;
- callback timing;
- callbacks depending on `this` context;
- code expecting multiple values from Promise-compatible objects;
- `$.when()` behavior.

Search:

```bash
rg -n "\.(then|pipe|done|fail|always|catch)\s*\(|\$\.when\s*\(" . \
  --glob '*.{js,html,php}'
```

---

### 7. Cross-domain script Ajax must be explicit

A cross-domain request that expects executable JavaScript must explicitly identify the response as script, for example:

```javascript
$.ajax({
  url: externalUrl,
  dataType: "script"
});
```

This behavior is also relevant to the security correction associated with old cross-domain Ajax behavior.

Search:

```bash
rg -n "\$\.(ajax|get|getScript)\s*\(" . --glob '*.{js,html,php}'
```

Review external URLs and dynamically constructed URLs.

---

### 8. `.context` and `.selector` removed

Search:

```bash
rg -n "\.context\b|\.selector\b" . --glob '*.{js,html,php}'
```

Review carefully because these property names can belong to non-jQuery objects.

---

### 9. `.on("ready", fn)` removed

```javascript
// Old
$(document).on("ready", fn);

// Replacement
$(fn);
```

Search:

```bash
rg -n "\.on\s*\(\s*['\"]ready['\"]" . --glob '*.{js,html,php}'
```

---

### 10. Dimensions may return fractional values

Methods such as `.width()` and `.height()` may return non-integer values in jQuery 3.x.

Risky code:

```javascript
if ($element.width() === 300) {
  // exact-integer assumption
}
```

Focus testing on:

- sliders;
- carousels;
- popup positioning;
- responsive menus;
- image galleries;
- calculated layouts.

---

### 11. `:visible` / `:hidden` behavior changed

Any plugin heavily dependent on visibility selectors should be regression tested.

Search:

```bash
rg -n ":visible|:hidden" . --glob '*.{js,html,php}'
```

---

### 12. Deprecated event APIs should be removed while here

jQuery 3.0 deprecated:

```text
.bind()
.unbind()
.delegate()
.undelegate()
```

Prefer:

```text
.on()
.off()
```

Search:

```bash
rg -n "\.(bind|unbind|delegate|undelegate)\s*\(" . --glob '*.{js,html,php}'
```

## Required migration tool

Use the development/uncompressed jQuery Migrate 3.x build while testing:

```html
<script src="jquery-3.0.0.js"></script>
<script src="jquery-migrate-3.x.js"></script>
```

Treat every JQMIGRATE warning as one of:

```text
FIX
DOCUMENTED / ACCEPTED TEMPORARILY
FALSE POSITIVE AFTER MANUAL REVIEW
```

Do not silently ignore warnings.

# Step 3 — 3.0.0 → 3.1.1

## Gap Summary

```text
3.0.0
   ↓
3.1.1

Primary gap:
Ready-handler error visibility + patch-level fixes.
```

### Verified upstream facts

jQuery 3.1.0 changed ready-handler exception handling so errors are no longer silently swallowed. Ready-handler errors are passed through `jQuery.readyException`; the default behavior rethrows them asynchronously so they appear in the console.

jQuery 3.1.1 is a patch release. The jQuery project stated that it introduced no new features or intended compatibility issues when upgrading from jQuery 3.0+.

3.1.1 fixed issues including:

- disabled-option selector behavior;
- `jQuery.noConflict` exposure with AMD;
- whitespace handling;
- source-map/debugging issues.

### Project risk assessment

**Risk: 🟢/🟡 Low–Medium**.

The main practical effect in a legacy application is that JavaScript errors that were previously hidden may become visible.

That is useful: treat newly visible exceptions as existing application defects rather than automatically assuming jQuery 3.1.1 caused them.

## Areas to inspect

```bash
rg -n "\$\s*\(\s*function|\.ready\s*\(" . --glob '*.{js,html,php}'
```

Test initialization code for:

- sliders;
- menus;
- modal libraries;
- form plugins;
- page builders;
- backend widgets;
- custom document-ready bootstrap functions.

## Exit Gate

```text
New ready-handler exceptions:     0 unresolved
AMD/noConflict integrations:      PASS or N/A
Critical initialization flows:    PASS
Regression suite:                 PASS
```

## References

- https://blog.jquery.com/2016/07/07/jquery-3-1-0-released-no-more-silent-errors/
- https://blog.jquery.com/2016/09/22/jquery-3-1-1-released/

# Step 4 — 3.1.1 → 3.2.1

## Gap Summary

```text
3.1.1
   ↓
3.2.1

Primary gap:
Dimensions + event edge cases + deprecation preparation.
```

### Verified upstream facts

jQuery 3.2.0 introduced bug fixes, improvements, and deprecations. The jQuery project stated that it did not expect compatibility issues when upgrading from jQuery 3.0+.

Notable 3.2.0 items include:

- support for CSS custom properties;
- deprecation of `jQuery.holdReady`;
- deprecation of `jQuery.nodeName`;
- deprecation of `jQuery.isArray`;
- dimension calculation corrections.

jQuery 3.2.1 quickly followed as a hotfix release for regressions introduced in 3.2.0, especially:

- width/height retrieval for inline elements;
- radio click event behavior/data.

### Project risk assessment

**Risk: 🟡 Medium** if the application has layout-heavy widgets or manually triggered checkbox/radio events.

Otherwise the gap is generally small once the application is already stable on jQuery 3.x.

## Code to inspect

Deprecated APIs:

```bash
rg -n "\$\.holdReady\s*\(|\$\.nodeName\s*\(|\$\.isArray\s*\(" . \
  --glob '*.{js,html,php}'
```

Dimension-heavy code:

```bash
rg -n "\.(width|height|innerWidth|innerHeight|outerWidth|outerHeight)\s*\(" . \
  --glob '*.{js,html,php}'
```

Manually triggered input events:

```bash
rg -n "\.trigger\s*\(\s*['\"]click['\"]|\.click\s*\(" . \
  --glob '*.{js,html,php}'
```

## Focus testing

- [ ] Inline-element dimensions.
- [ ] Slider/carousel width calculations.
- [ ] Popup centering/positioning.
- [ ] Checkbox behavior.
- [ ] Radio-button behavior.
- [ ] Form validation plugins.
- [ ] CSS custom property usage, if any.

## Exit Gate

```text
Dimension regressions:            0
Radio/checkbox regressions:        0
Deprecated APIs:                  documented/fixed
Critical UI suite:                PASS
```

# Step 5 — 3.2.1 → 3.3.1

## Gap Summary

```text
3.2.1
   ↓
3.3.1

Primary gap:
Large deprecation inventory, but no intended 3.x compatibility break.
```

### Verified upstream facts

jQuery 3.3.0 deprecated several APIs while keeping them available. The project stated that it did not expect compatibility issues for applications already using jQuery 3.0+.

The deprecation list included:

```text
jQuery.now
jQuery.isWindow
jQuery.camelCase
jQuery.proxy
jQuery.type
jQuery.isNumeric
jQuery.isFunction
Event alias methods
```

jQuery 3.3.0 also added support for passing arrays to:

```text
.addClass()
.removeClass()
.toggleClass()
```

jQuery 3.3.1 contains the same runtime code as 3.3.0; it corrected release/package dependencies and became the recommended package version.

### Project risk assessment

**Risk: 🟢/🟡 Low–Medium**.

Existing code should normally continue working. The important task is to identify technical debt before later upgrades.

## Code to inspect

```bash
rg -n "\$\.(now|isWindow|camelCase|proxy|type|isNumeric|isFunction)\s*\(" . \
  --glob '*.{js,html,php}'
```

Event aliases:

```bash
rg -n "\.(click|dblclick|focus|blur|change|select|submit|keydown|keypress|keyup|mousedown|mouseup|mousemove|mouseover|mouseout|mouseenter|mouseleave|resize|scroll)\s*\(" . \
  --glob '*.{js,html,php}'
```

> Event alias matches are not automatically bugs. Review them and prefer `.on(event, handler)` in code being modernized.

# Step 6 — 3.3.1 → 3.4.1

## Gap Summary

```text
3.3.1
   ↓
3.4.1

Primary gap:
Security correction in deep object merge + event/selector changes.
```

### Verified upstream facts

jQuery 3.4.0 fixed prototype pollution in deep `jQuery.extend()` operations involving an enumerable `__proto__` property.

Example vulnerable pattern in older jQuery:

```javascript
$.extend(true, {}, JSON.parse(userControlledJson));
```

jQuery 3.4.0 also:

- improved `.width()` / `.height()` behavior/performance;
- changed radio event behavior so state is updated before handlers run;
- added support related to script `nonce` / `nomodule` attributes;
- deprecated non-standard positional selectors including `:first`, `:last`, `:eq`, `:even`, `:odd`, `:lt`, `:gt`, and `:nth`.

jQuery 3.4.1 then fixed regressions introduced by 3.4.0, including repeated focus/blur triggering in IE and element-attachment behavior in older iOS 10 versions.

### Security milestone

This checkpoint addresses:

```text
CVE-2019-11358 — Prototype Pollution
```

### Project risk assessment

**Risk: 🟡 Medium**.

Most ordinary application code should remain compatible, but deep merges of untrusted objects and event-sensitive widgets deserve focused testing.

## Code to inspect

Deep `$.extend()`:

```bash
rg -n "\$\.extend\s*\(\s*true" . --glob '*.{js,html,php}'
```

For every match determine where the source object comes from:

```text
STATIC APPLICATION OBJECT       → lower risk
SERVER RESPONSE                 → review
URL / QUERY DATA                → high priority
USER-SUBMITTED JSON             → high priority
THIRD-PARTY API DATA            → review
```

Positional selectors:

```bash
rg -n ":(first|last|eq|even|odd|lt|gt|nth)(\(|\b)" . \
  --glob '*.{js,html,php}'
```

Prefer positional methods where practical:

```javascript
// Instead of a jQuery-only positional selector
$(".item:first")

// Prefer
$(".item").first()
```

## Focus testing

- [ ] Deep merge/configuration utilities.
- [ ] Ajax response → object merge flows.
- [ ] Radio button widgets.
- [ ] Focus/blur-driven widgets.
- [ ] Selector-heavy plugins.
- [ ] Sliders and galleries using positional selectors.
- [ ] CSP/nonce-sensitive dynamically inserted scripts, if applicable.

## Exit Gate

```text
Unsafe deep merge paths:          0 unresolved
CVE-2019-11358 version exposure:  CLOSED
Event regressions:                0
Selector regressions:             0
Regression suite:                 PASS
```

# Step 7 — 3.4.1 → 3.5.0

## Gap Summary

```text
3.4.1
   ↓
3.5.0

Primary gap:
Security-driven HTML parsing behavior change.
```

### Verified upstream facts

jQuery 3.5.0 changed `jQuery.htmlPrefilter()` to stop rewriting XHTML-style self-closing tags. The old rewriting behavior could transform certain HTML strings in a way that introduced XSS risk.

Before 3.5.0, input similar to:

```javascript
$("<div/><span/>");
```

could be rewritten as though it were:

```html
<div></div><span></span>
```

Starting with jQuery 3.5.0, the HTML string is passed through without that legacy rewrite. Browser HTML parsing can therefore produce a different DOM structure for invalid self-closing syntax on non-void HTML elements.

jQuery 3.5.0 also fixed another similar XSS issue involving `<option>` handling in DOM-manipulation paths.

### Security milestone

This checkpoint addresses:

```text
CVE-2020-11022
CVE-2020-11023
```

### Project risk assessment

**Risk: 🟠 High** for legacy applications that dynamically construct HTML strings.

This is not a normal cosmetic change. The compatibility change exists because restoring the old behavior can also restore the security exposure.

## High-risk code patterns

### 1. Self-closing non-void HTML elements

Search:

```bash
rg -n "<(div|span|p|section|article|a|li|ul|ol|table|tr|td|form|label|button|select|option)[^>]*\s*/>" . \
  --glob '*.{js,html,php}'
```

Potential fix:

```javascript
// Avoid
$("<div class='box'/>");

// Prefer
$("<div class='box'></div>");
```

---

### 2. `.html()` with dynamic input

Search:

```bash
rg -n "\.html\s*\(" . --glob '*.{js,html,php}'
```

Classify each relevant match:

```text
STATIC CONSTANT HTML            → lower risk
SERVER-GENERATED HTML           → review trust/sanitization
USER-CONTROLLED DATA            → high risk
THIRD-PARTY API HTML            → high risk
QUERY / URL DERIVED HTML        → high risk
```

---

### 3. DOM insertion methods

Search:

```bash
rg -n "\.(append|prepend|before|after|replaceWith|wrap|wrapAll|wrapInner)\s*\(" . \
  --glob '*.{js,html,php}'
```

Review any operation inserting HTML strings from untrusted or partially trusted sources.

---

### 4. Dynamic `<option>` construction

Search:

```bash
rg -n "<option|new Option|\.append\s*\(.*option" . --glob '*.{js,html,php}'
```

Focus on dropdowns populated from Ajax or user-controlled data.

---

### 5. Custom `jQuery.htmlPrefilter`

Search:

```bash
rg -n "htmlPrefilter|UNSAFE_restoreLegacyHtmlPrefilter|migrateEnablePatches" . \
  --glob '*.{js,html,php}'
```

### Security warning

Do **not** treat restoring the legacy prefilter as the final fix.

jQuery Migrate can temporarily restore legacy behavior for migration diagnostics, but restoring that behavior weakens the security benefit of the 3.5 change. The correct long-term solution is to fix invalid HTML generation and sanitize untrusted HTML correctly.

## Focus testing

- [ ] Dynamic HTML widgets.
- [ ] Ajax-rendered fragments.
- [ ] Dropdowns and `<option>` creation.
- [ ] Modal contents.
- [ ] Tooltips/popovers.
- [ ] Page-builder blocks.
- [ ] Slider/carousel markup generated in JavaScript.
- [ ] Form builders.
- [ ] HTML templates embedded in JavaScript.
- [ ] Security scan for CVE-2020-11022 / CVE-2020-11023.

## Exit Gate


# Step 8 — 3.5.0 → 3.5.1

## Gap Summary

```text
3.5.0
   ↓
3.5.1

Primary gap:
Regression fix.
```

### Verified upstream facts

jQuery 3.5.0 changed an internal data object to use `Object.create(null)`. This broke code, especially plugins, that expected jQuery's data object to support the native `.hasOwnProperty()` method.

jQuery 3.5.1 reverted that internal data-object change. The jQuery project stated that this was the only code change in the 3.5.1 release.

The security fixes introduced in 3.5.0 remained in place.

### Project risk assessment

**Risk: 🟢 Low**.

In most cases `3.5.1` is safer operationally than remaining on `3.5.0` because it keeps the 3.5 security fixes while correcting the data-object regression.

## Code to inspect

Search plugin/data introspection:

```bash
rg -n "hasOwnProperty\s*\(|\$\._data\s*\(|\$\.data\s*\(|\.data\s*\(" . \
  --glob '*.{js,html,php}'
```

Not every `.data()` match requires change. Focus on code that reads or iterates internal jQuery data structures.

## Focus testing

- [ ] Plugins using `.data()` heavily.
- [ ] Widgets storing state in jQuery data.
- [ ] Plugin initialization/destruction cycles.
- [ ] Repeated modal/slider/widget initialization.
- [ ] Confirm 3.5.0 XSS fixes remain effective.

## Exit Gate

```text
jQuery runtime version:          3.5.1
```
